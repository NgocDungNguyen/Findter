# Findter Filter & Search: home screen replica

A single-file, static replica of the **Findter Filter & Search** app home screen inside the Shopify admin (desktop and mobile), plus a small "Master UI" area for arranging the homepage.

Open [`index.html`](index.html) in a browser. There is no build step and no server. It needs an internet connection for the Inter font and the app icons (loaded from Shopify's CDN).

## What's inside

- **Homepage:** onboarding guide (expand/collapse, four steps), recommended apps carousel, data insight with date picker and tooltips, app status, help & support, sync, and the Shopify admin shell (sidebar, collapsed rail, mobile drawer, search, menus, Sidekick bar).
- **Master UI** (`#/master`, via the **Master** card): tabs, and a **Home** tab where you
  - drag and drop blocks between the desktop left / right columns,
  - set a separate order for phones,
  - move the **Promotion** block (left column and phone order only). Promotions themselves are created in the **Promotion** tab of Master: a promotion goes live on the homepage as soon as it is saved, and the block shows every live promotion that targets the shop (arrows switch between them). A promotion has a name, SKU, deadline, desktop (633×160) and mobile (370×185) image, the shop types that see it, and one action: open a link (required) with an optional promo code, which is copied on the way and announced by a "Code: … copied successfully" note on the page that opens. The header **demo bar** (Store / Plan / Date / Products / Language; a "Demo data" drop-down below 1860px) fakes the shop so targeting and the **Findter app status** box can be tested. The box follows the RQM "Update: Findter Block app status" (PMS #877): Plan badge per store type (Development, Trial, Advanced trial, plan name, Free, Legacy), one date row (Expires on / Renew on / Ends on, orange at 7 days or less, month name in the chosen language), Products indexed "x / y" ("∞" without a limit; orange over the limit or while a sync runs), and the app's own limit banner for each case on top of the left column. `tools/rqm-status-shots.js` checks every case and writes numbered pictures to `RQM Images - App status/` (not committed).
- All Master changes are a **draft until you click Save**. Saved data lives in the browser's `localStorage`; nothing is sent to a server.
- Dismissing a block with its **X** only lasts until the page is reloaded.

**"Powered by Findter" badge** (watermark touchpoint): a small text under the search suggestions on the storefront. The tab copies the real app (static **Features** and **Recommended Apps** containers, nothing in them works) and adds the **Powered by Findter badge** container under them: title, **Enable the badge** tickbox, **Apply to** (each shop type with its note, like Promotion) and its own **Save** inside the container (no Discard). A draft until Save, stored in `localStorage` (`findter.watermark.v1`). (2) **Search settings** shows a card with one row, **Remove “Powered by Findter” badge** (tooltip + a text **Remove** button, no heading or description), between the info banner and "Search field", only for a ticked shop type. Every store type first sees the **Remove** button (nobody turns the badge back on). Clicking it is one click, no questions: a **Trial / Free** shop (never paid) gets the chat with the shop's message, about a second later the badge is removed and the support team replies "I have already removed… Is there anything else I can help you with, or any feedback…?" (so a CSE can follow up whether or not one is online), the button reads **Removing…** for about a second, and then it becomes a green **Removed** badge; clicking again meanwhile sends nothing twice. A shop that has **paid** (Subscription, Paid before, Service) skips the chat: its button becomes **Removed** at once. (3) `storefront.html`, a sample collection page with the header search and suggestions, opened by **Online Store** under Sales channels in the sidebar (new tab); the badge hangs under the right corner of the suggestions box and follows the admin tab live. The bar's **Reset** button puts every demo value back to its start (Trial store, 14 days, normal products, English, badge shown) and cancels a removal that is still on its way, so a store type is not stuck on "Removed". Promotion banners (Master → Promotion) can link to these pages with shortcuts: `/filter`, `/filter-booster`, `/search`, `/search-booster`, `/metafield`, `/ymm`, `/features`, `/design`, `/product-grid`, `/pricing`. A shortcut opens in the same tab; an `https://` link opens a new tab. With a promo code, "Code: … copied successfully" shows under the header of the page that opens (`tools/build/code-notice.js`).

The sidebar and the sub-page tabs link between all of these pages. They copy only what you see when they first open: buttons that would open settings, nested options and modals show a short "not part of this copy" message. The status toggles, the search-field checkboxes + Save, the two design pages (all settings and previews) and the phone-width table scroller do work.

All pages except `index.html` share files in `assets/`: `common.css` (all styles), `shell.js` (sidebar, menus, search overlay, Sidekick bar), `pages.js` (page behaviour) and `img/` (the app's own images). Edit a page's own markup in its `.html` file; change anything shared in `assets/`. They are generated by `node tools/build-pages.js` (run after `node tools/build.js`), so a rebuild overwrites hand edits to these files: make lasting changes in `tools/build/` instead.

## Design rules

[`design-rules/`](design-rules/README.md) lists everything to follow when designing UI/UX for the Shopify app (tokens, layout, components, tone, repo conventions) and a pre-ship checklist based on [`Built For Shopify.txt`](Built%20For%20Shopify.txt). `CLAUDE.md` makes consulting them a standing rule.

## Layout rules

- Up to 767px wide the page uses the single-column **mobile layout**, using the order from the *Mobile phone order* list. Default order: Findter app status, Sync recent updates, Onboarding guide, Help & Support, Data insight, Promotion, Recommended apps, Master. On desktop the left column is Onboarding guide, Data insight, Promotion, Recommended apps, Master and the right column is Findter app status, Help & Support, Sync recent updates.
- Every block shares one width (10px side margins) on mobile.

## Tooling

`tools/` holds the scripts used to build `index.html` (`node tools/build.js`): it flattens the app's web components to plain HTML, trims the Polaris CSS to the classes in use, and assembles the page together with the hand-written shell (`tools/build/`). The raw captures of the live admin (`tools/cap`) and local browser profiles are **not** part of the repository, so the build can't be re-run from a clean checkout. `index.html` is the deliverable.

This is an unofficial UI replica for design/prototyping. Shopify, Polaris and Findter belong to their respective owners.
